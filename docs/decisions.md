# Decisions

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 12 Oct | Build a dashboard with stability score and email caution notices; application team approved the approach | Project goal |
| D2 | 21 Oct | No server names, IPs or credentials in documents or code; placeholders everywhere | Security requirement from the user |
| D3 | 22 Oct | Proceed on documented assumptions where the application team does not answer; every rule configurable in rules.yaml | Not all questions will be answered |
| D4 | 20 Oct | Notices by email only; no ticket creation | Application team answer (Q33) |
| D5 | 20 Oct | First notice after 15 min down, 5 min during month-end/quarter-end close | Application team answers (Q31, Q34) |
| D6 | 20 Oct | Multi-node components: Degraded, score reduced by node share | Application team answer (Q27) |
| D7 | 3 Nov | Architecture option A: own service polling servers directly | New Relic covers no EPM service in production; API access delayed. Pending formal sign-off (A12) |
| D8 | 27 Oct - 3 Nov | Monitor Foundation, HFM Web and FR Web as separate components | Discovery: three separate services and clusters |
| D9 | 3 Nov | FR RMI and LCM not monitored | Discovery: FR RMI service does not exist; no scheduled LCM jobs |
| D10 | 3 Nov | Store all times in UTC | Servers run in different time zones |
| D11 | 4 Nov | Use personal Remote Desktop credentials only for temporary development testing, never in production | Audit, lockout and policy risk |
| D12 | 4 Nov | A node whose checks cannot run (Unknown) is left out of its component's node share; a component with no checkable node is left out of the overall score. Configurable as `scoring.unknown_nodes` (`exclude` / `count_as_down`) | A monitoring fault, such as lost WinRM access, should not lower the score or trigger the 0% cap. ASSUMED Q53, awaiting the application team |
| D13 | 4 Nov | Several checks on one node: worst result wins, in the order Down > Degraded > Unknown > Up. While a failure is not yet confirmed the node keeps its previous status; recovery shows straight away | A definite failure tells more than "could not check"; flap protection (Q40) should delay Down, not Up |
| D14 | 4 Nov | Component status: all nodes Up = Up, all nodes Down = Down, anything else = Degraded. A hard dependency caps the overall score only when the whole component is Down. Overall score rounded to 2 decimals before choosing the band | Follows Q27 (node share) and Q28 (OHS caps only when all nodes are down); rounding stops float noise from changing the band |
| D15 | 4 Nov | rules.yaml is checked strictly at start-up: unknown or duplicate keys, out-of-range values and broken references stop the program. `auto_restart: false` and UTC storage are enforced by the check itself | Hard rules 3, 5 and 6 in CLAUDE.md; a typo must not quietly fall back to a default |
| D16 | 4 Nov | Code layout: `src/hfm_dashboard/domain` (no I/O), `config/`, then `ports/`, `adapters/`, `app/`. A test blocks I/O imports in the domain | Ports-and-adapters design (CLAUDE.md); every adapter can be replaced by a fake in tests |
| D17 | 10 Nov | Collectors report raw observations only; `domain/evaluation.py` turns them into a status using `rules.yaml checks:`. A metric the collector could not read, or a state not listed in rules.yaml, counts as Unknown (a definite Degraded/Down still wins, D13). "Above"/"longer than" thresholds are strict (>), "below" is strict (<). A URL probe with no response or past `timeout_seconds` is Down; an HTTP code in neither `up_on_http_status` nor `down_on_http_status` is Degraded (ASSUMED Q54). A WebLogic server in a Down state skips the heap/stuck-thread checks. With `down_if_service_not_running: false` the SQL check ignores the service state (the windows_service check still covers it) | Keeps every threshold in rules.yaml and collectors simple and replaceable; a missing reading must not pass as healthy |
| D18 | 10 Nov | One monitoring service watches every environment in `environments.yaml`. An environment may have fewer nodes than rules.yaml (development has one of each); a rules.yaml node an environment does not declare is not monitored there. Start-up is refused if: any `{{PLACEHOLDER}}` remains in a value (comments ignored); an enabled component has no node in an environment; a declared node is used by no component; a node of a component with a windows_service check has no service name; a service entry names an unknown component or a node that is not declared or not in the component; an environment is missing from rules.yaml `environments`; or `notices_enabled` in environments.yaml disagrees with rules.yaml (rules.yaml decides; the key is optional). Error messages show paths and placeholder names, never filled-in values | Requirement 4 (per-environment view) and hard rules 1, 4 and 6; catches typos without forcing development to copy the production topology |
| D19 | 10 Nov | Windows services collector: one read-only `Get-Service` PowerShell script per host over WinRM (pypsrp), hosts queried in parallel. Service matched by Name, then DisplayName, case-insensitive; no match = `NotFound` (Down). Authentication uses the service's own gMSA identity (Negotiate/Kerberos), so no password is stored; an explicit credential is accepted only for development testing (D11). WinRM port, SSL and auth mode live in `environments.yaml` (`winrm:`); the per-host timeout in rules.yaml (`checks.windows_service.timeout_seconds`, ASSUMED Q40, below the poll interval). A host that cannot be queried gives Unknown for every service on it; error text shown is fixed per failure type, never the exception message | Hard rules 1-4; some service names were recorded from the DisplayName column in discovery; exception messages can carry user names or URLs |
| D20 | 17 Nov | Operator command `hfm-check-services` runs the services collector for one environment and can record masked raw responses. Only the chosen environment's block must be filled in (the monitoring service still validates the whole file). Output uses node keys, not hosts. Recording masks every host (FQDN, short name, DNS suffix) with a node-key-based `example.test` name, plus the user name and IPv4 addresses, then re-scans and writes nothing if anything is left. `--username` prompts for the password and is refused for PROD (D11) | Lets the client environment produce fixture data safely (hard rule 1) without filling production values; a masking gap must fail closed |
| D21 | 17 Nov | WebLogic collector: one bulk-access `POST .../domainRuntime/search` to the Admin Server per poll (reads only; no other endpoint), HTTP basic auth with the read-only Monitor user from the secret store. Lifecycle state from `serverLifeCycleRuntimes` (covers stopped servers); health, stuck-thread count and heap (100 - heapFreePercent) from `serverRuntimes`. Health is a separate map in rules.yaml (`health_up/degraded/down`, ASSUMED Q22); `WARNING` moved out of the lifecycle list (it is a health value); STARTING / SHUTTING_DOWN added as Degraded and FAILED_NOT_RESTARTABLE as Down. Admin Server unreachable = every WebLogic check Unknown (the windows_service checks still cover the servers). Server names per node in `environments.yaml weblogic.servers`, cross-checked like service names. Secrets via a `SecretStore` port; interim adapter reads environment variables until Q55 is decided | One request keeps load on the Admin Server minimal; separating health from lifecycle matches WebLogic's model; the store choice must not block the build |
| D22 | 17 Nov | URL probes: per-node probes go straight to each web node's managed-server port (`environments.yaml url_probes`: scheme, port key and path per probe), because OHS balances across both nodes and would hide which one failed. Probes through `load_balancer.url` run for components with `lb_probe: true` (OHS / load balancer) and are reported under the reserved node `load_balancer`, kept out of scoring until Q57 is answered. Plain GET, no credentials, redirects not followed (first response judged and timed), full body read. TLS verified against the Windows certificate store (truststore), also for the WebLogic adapter, so a corporate CA works. Details name probe and path, never host or URL | Node-level visibility for active-active web tier; the LB's scoring effect is an application-team decision; certifi does not contain corporate CAs |
| D23 | 17 Nov | SQL Server collector: one ODBC connection per database node (ODBC Driver 18, `ApplicationIntent=ReadOnly`, encrypted), Windows authentication with the service's gMSA by default or a SQL login from the secret store (`environments.yaml sql.auth`). Eight read-only SELECTs against DMVs and msdb, each its own query so a missing permission blanks only that metric (Unknown). Log use limited to the EPM databases in `environments.yaml databases`; disk free per volume holding database files; deadlocks from the system_health session (last 15 min); ages computed on the server so its time zone never matters. Connection failure = Unknown (a stopped service is Down via the windows_service check). Backups: SQL Server records only successful backups, so the rule became `degraded_if_no_backup_in_last_hours` (full or differential, per EPM database, ASSUMED Q59). Connection string never logged; errors mapped from SQLSTATE to fixed texts | Least privilege, read-only (hard rule 3); one failing DMV must not hide the rest; a failed backup is not visible in msdb |
| D24 | 17 Nov | Poll loop: per environment, the four collectors run in parallel each poll; results are folded per node (worst check wins; an expected check with no result, e.g. from a crashed collector, counts as Unknown), then flap protection (`status.advance`), then scoring limited to the nodes the environment has (`score(..., component_nodes)`, so `count_as_down` never penalises a smaller non-prod). One APScheduler job per environment every `poll_interval_seconds`, `max_instances=1`, `coalesce=True`, plus a non-blocking lock in `Poller.poll_once`: an overlapping poll is skipped and logged. A collector whose credential is missing reports Unknown with the reason instead of stopping the service. Node states live in memory until the history store exists. Library INFO logging (pypsrp, httpx, ...) is lowered to WARNING; log timestamps in UTC | A collector fault must never look healthy; polls must not pile up when a probe hangs for the whole interval; access arrives piecemeal (A06-A11) |
| D25 | 17 Nov | Status history in SQLite on the monitoring server (`<data-dir>/history.sqlite`, default `data/`, git-ignored) behind a `HistoryRepository` port: one row per poll (score, band, cap, duration, collector errors), current node state per node (upserted), and every confirmed status change (`Transition`, computed purely in `domain/snapshot.py` and carried in each snapshot for the notice engine). Node states are restored at start-up (limited to nodes still monitored), so "down since" and flap counters survive a restart and a node already Down raises no new transition. Rows older than `collection.history_retention_days` are purged every 6 h; current states are never purged. One connection with a lock, WAL journal, atomic write per poll, schema version in `PRAGMA user_version` (a newer version is refused). A failing history store is logged and never stops polling; one that cannot be opened at start-up refuses start (exit 2); `--no-history` for dry runs | CLAUDE.md: history off the EPM SQL Server; restarts must not reset outage timers or re-trigger notices |
| D26 | 17 Nov | URL probe failures that only show the host cannot be reached from the monitoring server count as Unknown, not Down: DNS failure, network or host unreachable, connect timeout (no answer at all), TLS / certificate and proxy errors. Refused connections (host up, nothing listening), read timeouts, dropped connections and HTTP codes in `down_on_http_status` stay Down. Amends D17 for URL probes; consistent with WinRM / WebLogic / SQL connection failures, which were already Unknown. Consequence: a server that is switched off or cut off from the network shows Unknown on every check and is left out of the score (`unknown_nodes: exclude`, Q53); the notice engine must therefore warn when a node stays Unknown (slice 12) | Decided by the user 17 Nov: a monitoring-side network fault must not show the application Down or send owner notices |
